Esta semana el patron ha sido bastante claro: las noticias importantes no van de una IA mas espectacular en una demo, sino de agentes entrando en flujos reales con herramientas, costes, trazabilidad y supervision.

Mi lectura: estamos pasando de probar modelos sueltos a construir sistemas donde la IA tiene que hacer trabajo, dejar evidencia y permitir que una persona revise antes de cerrar el ciclo.

La idea de fondo: un agente util no es el que promete hacerlo todo. Es el que sabe recibir contexto, usar herramientas, avanzar una tarea y dejar el siguiente paso preparado para revision.

Lo mas importante en IA esta semana

1. Anthropic lanza Claude Sonnet 5

Anthropic ha presentado Claude Sonnet 5, disponible en Claude, Claude Code y API. La parte importante no es solo que sea otro modelo nuevo. Lo interesante es el posicionamiento: mas capacidad agentica, mejor relacion coste-rendimiento y uso mas razonable para tareas largas donde antes mucha gente tiraba de modelos mas caros.

Que cambia para un negocio: cada vez tiene mas sentido separar tareas por nivel de riesgo y coste. No todo necesita el modelo mas caro. Un buen sistema puede usar un modelo eficiente para preparar, clasificar, resumir o ejecutar pasos repetibles, y reservar modelos superiores para decisiones mas delicadas.

Que no exageraria: no convierte cualquier proceso malo en uno bueno. Si el flujo esta mal definido, el modelo solo hara mas rapido el desorden.

Fuente: Anthropic

2. Vercel presenta AI SDK 7 para construir agentes

En Vercel Ship 2026, Vercel presento AI SDK 7 como una herramienta para crear agentes que razonan, llaman herramientas, trabajan en varios turnos y operan con archivos y sandboxes usando una interfaz comun entre proveedores.

Que cambia para un negocio: esto refuerza una idea clave: los agentes no viven dentro del chat, viven conectados a herramientas. La utilidad aparece cuando pueden leer datos, llamar APIs, preparar archivos, actualizar estados y dejar trazas.

Mi lectura: no empezaria preguntando que agente construir. Empezaria preguntando que proceso se repite cada semana y que paso queda siempre pendiente por falta de tiempo.

Fuente: Vercel

3. GitHub Copilot avanza en agentes dentro del entorno de trabajo

GitHub anuncio que Copilot Agent ya esta disponible dentro de JetBrains AI Assistant. Tambien abrio en preview el streaming de actividad de sesiones de agente para empresas, con visibilidad sobre prompts, respuestas y llamadas a herramientas.

Por que importa: aqui hay dos movimientos a la vez. Por un lado, el agente entra donde ya trabaja la persona. Por otro, la empresa empieza a poder auditar que ha hecho ese agente.

Aplicacion practica: en automatizacion pasa lo mismo. Un flujo serio no deberia limitarse a ejecutar. Debe guardar que recibio, que decidio, que herramienta uso, que cambio hizo y que queda pendiente de aprobacion.

Fuentes: GitHub Copilot en JetBrains y GitHub session streaming

4. Cursor lleva sus agentes al movil

Cursor lanzo su app para iOS en beta publica para planes de pago. La noticia puede parecer menor, pero apunta a algo relevante: iniciar, revisar o desbloquear trabajo con agentes empieza a moverse fuera del escritorio.

Que cambia para negocios reales: no significa que haya que gestionar operaciones complejas desde el movil. Significa que ciertos pasos ligeros pueden hacerse en cualquier momento: revisar un borrador, pedir una investigacion, iniciar una tarea tecnica o dejar preparada una accion para mas tarde.

La advertencia: cuanto mas facil es lanzar tareas, mas importante es tener limites. Un agente sin contexto, sin criterio y sin revision puede generar trabajo extra en lugar de quitarlo.

Fuente: Cursor

5. Mistral publica Leanstral 1.5

Mistral presento Leanstral 1.5, un modelo abierto orientado a verificacion formal y pruebas en Lean. Es una noticia mas tecnica, pero merece entrar por el patron que representa: IA que no solo genera una respuesta, sino que intenta demostrar, verificar y encontrar fallos.

Lectura practica: para la mayoria de negocios, esto no va de usar Lean manana. Va de hacia donde se mueve el mercado: menos texto bonito y mas evidencia. La IA util sera la que deje una comprobacion, una prueba, una validacion o una razon clara para que una persona pueda decidir.

Fuente: Mistral AI

Lectura de Jaime

La semana deja una conclusion bastante sencilla: los agentes estan madurando cuando empiezan a parecer menos magia y mas operacion.

Mas modelos, mas SDKs, mas integraciones y mas apps moviles no solucionan nada por si solos. Lo importante es que cada vez hay mas piezas para cerrar ciclos completos: entrada, criterio, accion, registro y revision.

La IA ayuda, pero el criterio sigue siendo humano. Y precisamente por eso los mejores sistemas no intentan esconder lo que hacen. Lo dejan visible.

Aplicacion practica

Si tuviera que aplicar esta idea en una empresa pequena, no empezaria por meter un agente en todo. Empezaria por un proceso concreto donde ya haya repeticion y perdida de tiempo.

Por ejemplo:

  • Entradas de leads que llegan por formulario, WhatsApp o email.
  • Consultas frecuentes que alguien responde siempre parecido.
  • Facturas, documentos o solicitudes que se revisan manualmente.
  • Contenido que se crea, se adapta y se publica en varios canales.
  • Seguimientos comerciales que dependen de que alguien se acuerde.

El sistema bueno no seria: "que la IA lo haga todo". El sistema bueno seria: que la IA clasifique, prepare la respuesta, proponga el siguiente paso, guarde el registro y deje lo importante listo para aprobar.

Construyendo en publico

Esto conecta mucho con lo que estoy montando alrededor de automatizaciones, n8n, OpenClaw y sistemas propios.

La parte potente no es tener un agente respondiendo mensajes. La parte potente es que ese agente pueda trabajar dentro de un proceso real: leer contexto, decidir una ruta, llamar una herramienta, preparar un borrador, dejar evidencia y esperar aprobacion cuando toca.

Esto no va de producir mas ruido, sino de dejar el siguiente paso preparado.

Idea accionable para hoy

Elige un proceso repetitivo de tu negocio y haz este ejercicio en 15 minutos:

  • Escribe cual es la entrada: formulario, email, WhatsApp, hoja de calculo, pedido, factura.
  • Define cual es la salida deseada: respuesta, registro, tarea, aviso, propuesta, documento.
  • Marca que pasos son mecanicos y que pasos necesitan criterio humano.
  • Decide donde debe parar la automatizacion para pedir aprobacion.
  • Anota que evidencia deberia guardar: resumen, enlace, decision, fecha, responsable.

Con eso ya tienes el mapa base para construir un workflow util. Despues puedes decidir si lo haces con n8n, Make, Zapier, una API o un agente mas avanzado.

Pero el orden importa: primero proceso, despues herramienta.
